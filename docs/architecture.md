# Μηχανή διαθεσιμότητας — αρχιτεκτονική

Η πλήρης αρχιτεκτονική του B2B (μέλη, πύλη, ερωτηματολόγιο, SoftOne, δρομολόγηση) είναι στο eshop:
`euronics-redesign/docs/b2b-architecture.md`. Εδώ περιγράφεται μόνο η μηχανή.

## Ρόλος

```
 ERP / eshop μελών ──pull (API, feed)── ┐
                  ──push (POST /api/v1/stock)── ┤
                                                ▼
                          stock.euronics.gr (αυτό το repo, βάση euronics_stock)
                          connectors · έλεγχος σύνδεσης · secrets · ακατέργαστα · (Φ2) αντιστοίχιση
                                 ▲ ① γεγονότα + εντολές (HMAC)        │ ② projection (Φ2)
                                 │                                     ▼
                          euronics.gr (eshop): admin, πύλη B2B, login μελών, reporting, StoreAvailability
```

## Τι ανήκει πού

| Δεδομένο | Master | Εδώ |
|---|---|---|
| Μέλος, κατάστημα (= TRDBRANCH), σύνδεση (τύπος, ρυθμίσεις) | eshop | αντίγραφο με τα ίδια id (γεγονότα ①) |
| Λογαριασμοί, κωδικοί, ρόλοι μελών | eshop | **τίποτα** — η μηχανή δεν έχει χρήστες |
| Διαπιστευτήρια ERP/eshop των μελών | **μηχανή** | κρυπτογραφημένα (AES-256-GCM), δεν επιστρέφονται ποτέ |
| Κλειδιά push API | **μηχανή** | μόνο sha256 |
| Έλεγχοι σύνδεσης, ακατέργαστα δεδομένα, (Φ2) αντιστοίχιση προϊόντων/τοποθεσιών | **μηχανή** | |
| Τρέχουσα διαθεσιμότητα για το eshop | μηχανή → eshop | projection ② (Φ2) |

## Ασφάλεια

- **Εσωτερικά endpoints**: υπογραφή HMAC με χρόνο και nonce μίας χρήσης, και προαιρετικά λίστα IP.
- **Push API**: κλειδί ανά σύνδεση, που ανακαλείται αμέσως, και όριο συχνότητας.
- **Διευθύνσεις των μελών** (feeds, eshop, ERP): `lib/net/safe-fetch`.
  - Μόνο http/https, χωρίς εσωτερικές διευθύνσεις, με έλεγχο στη σύνδεση. Έτσι πιάνεται και το DNS rebinding.
  - Νέος έλεγχος σε κάθε redirect, όριο χρόνου και όριο μεγέθους.
- **Connectors μόνο διαβάζουν**. Ζητάμε πάντα χρήστη μόνο ανάγνωσης.
- **Logs**: ποτέ secrets ή payload. Στα μηνύματα σφάλματος φαίνονται μόνο ονόματα πεδίων.
